# Decisions API調査（2026-10-09）

提供状況は確認済み。ユーザー承認後に実API測定を完了。サブスクリプション担当を動かしても、この専用endpointの品質・速度の代わりにはならない。

[公式仕様](https://developers.openai.com/api/docs/guides/decisions)によると公開βで、対応モデルはgpt-6-lunaのみ。画像入力、predicate/choice/score、複数質問に対応。scoreは順序付き段階の確率加重平均で、整数の段階と異なり小数を返す。各段階の確率とconfidenceも返す。公式速度表記はResponses比約10倍だが、当ゲームの実測値ではない。

料金はDecisions入力100万tokenあたり$0.10、出力の課金はない。API認証・別のAPI課金が必要。当初のユーザー指示にAPI key使用・API課金を避ける条件があったため、ユーザーが最大$1の実測と既存キー使用を承認し、指定された~/.zshrcのコメント付きOPENAI_API_KEY設定からキーをプロセス内だけで読んで使用した。シェルファイルはsourceせず、キーを表示・保存していない。認証とDecisions利用は実測で成功した。

## このゲームへの対応

rubric-v2の4軸を4つのscore質問とし、0〜6の7段階説明をそのまま渡す。1画像/お題を1リクエストへ入れ、教師値は渡さない。共通v3から画像評価の指示だけを転用し、評価担当のモデルmetadataやJSON出力指定は除く。質問・rubricのhashを記録し、実測中に修正しない。

連続値のscoreを既存Fへ直接入れることはできない。Fは整数段階の非線形変換とお題上限を含む。今回、最頻段階MAP（同率時は低い段階）にFを適用した点差・順位・同点を比較し、連続値の平均段階MAEは別に出す。平均段階と最頻段階を混同しない。連続値を生かした本番得点は将来の別設計。

Decisionsは今回の型付き回答で文章の根拠や講評を返さない。現行のaxis_evidence付き評価へ偽の根拠を足さず、raw回答・確率・計算結果を別ファイルに保存する。採点後に一般LLMで講評する構成が合うが、その追加呼出し時間/費用は今回の採点単独測定には含めない。

## 実測を準備した内容

- 人間確認済み開発17作品と新規Sol教師18作品を別集計。18件の教師は人間未確認。
- 各2回＋除外するウォームアップ1回＝計71回。逐次実行、30秒timeout、自動リトライなし。
- 段階MAP/平均段階MAE、Fゲーム点MAE、順位相関、2段階差、5点以内、反復差。
- 成功と全試行の往復時間p50/p95、失敗/拒否/利用不可、usageと概算費用。画像送信とネットワークを含む採点単独時間。
- Responsesを同時に実測していないので「何倍速い」とは結論しない。過去のサブエージェントの所要時間も比較に使わない。
- 最大$1の承認を想定し、71回について保守的に$0.71を予約する。各回10万入力token相当を仮置きした見積であり、アカウント側の厳密な課金上限ではない。

`benchmark-decisions.mjs`は既定でdry-run、キーを取得せずネットワークも呼ばない。今回のdry-runは35作品のhash/サイズを確認し71回を計画、準備段階のAPI呼出しは0。その後の承認済み実行は71回。`--execute --allow-paid-api --max-cost-usd 1 --secret-id draw/openai-api-key --out tools/draw-evaluation/data/decisions-20261009-live`はユーザー承認後のみ使用する。今回の実行は同じ有料実行フラグを使い、Secret取得の代わりにユーザー指定の既存キーを子プロセスの環境へ渡した。原回答はGit管理外dataへ保存。Secretsの値、Authorization、画像base64はログに出さない。可用性・認証・rate limit・型契約エラーで停止する。

集計: `node tools/draw-evaluation/analyze-decisions.mjs tools/draw-evaluation/data/decisions-20261009-live`。rawの検証で拒否、軸重複、確率不正、平均値不整合をエラーにする。本番モデル・ランキングは変更しない。
