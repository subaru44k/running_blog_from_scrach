# Luna専用promptの調整手順

モデル別promptを認め、rubric-v2 / score-v2 / game-score-v1は共通に固定する。Sol v3は教師候補とし、人間が妥当とした評価のみ開発目標にする。モデルの一致は人間への妥当性と同義ではない。

今回の固定分割は調整17作品、最終13作品（同一画像1件を除外）、教師として隔離11作品。IDと画像SHA256の両方で重複を排除する。分割明細はローカル data/luna-tuning-split.json。最終13作品（同一画像1件を除外）は過去v1/v2で使った保存作品なので完全な未見データではなく、v3/Luna調整に未使用の確認集合。

調整集合だけを使って最大2改訂を試す。既存Luna v3予備評価を基準とし、段階MAEを第一指標、Fゲーム点MAEを同率時の第二指標とする。試行間の生成ばらつきも含むため、小さい改善を保証と解釈しない。

候補を選択したら、prompt全文のSHA256・分割SHA256・選択指標・日時をdata/luna-tuning-freeze.jsonに固定する。その後に最終13作品（同一画像1件を除外）の新規Sol v3教師、Luna v3基準、選択Luna promptのblind結果を開き、一度だけ比較する。評価担当には教師値を渡さない。最終結果を見てpromptを修正する場合は、その集合は次回の調整集合へ移し、別の新規作品を最終集合にする。

最終Sol教師の人間レビューは別途必要。最終集合の動物種や品質範囲に不足があれば追加の新規セットを用意する。今後のモデル変更も、教師の人間確認→分割→モデル専用prompt→固定→最終評価→人間確認の順に行う。サブスクリプションlowの結果はAPI noneの品質や実行時間を証明しない。本番モデル変更と過去ランキング更新は自動実施しない。

公式資料: [Evaluation best practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices)。代表的な実データ、明確な指標、人間評価との校正、継続評価を参考にした。

GPT-5.6 Lunaの2026-10-06検証は、以前の最終13件を再利用せず、既存42件と画像hash/IDで非重複の新規保存画像18件を最終集合に固定。調整17件のみで共通v3と最大2専用案を比較し、開発教師を一般化した少数の文章採点例はpromptに含めてよい。候補固定と最終評価はluna56専用スクリプト・明細として旧実行を保持する。
